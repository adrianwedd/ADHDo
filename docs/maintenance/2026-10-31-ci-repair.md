# Legacy CI repair — 31 October 2026

This follows the initial [maintenance sweep](2026-10-31.md) and addresses #119.
It restores installation and executable source paths, but does **not** establish
that the legacy application or all its tests are healthy.

## Implemented

- Replace nonexistent OpenTelemetry distribution/version declarations with the
  actual instrumentation packages. Keep API/SDK/exporters on the compatible
  1.21/0.42 family required by the retained Jaeger exporter, and retain
  `setuptools<81` for that instrumentation's `pkg_resources` dependency. This is
  a compatibility repair; migrating the retired Jaeger transport is still needed.
- Declare imported auth, QR, ML and test dependencies; include sibling source
  packages in the built wheel. CI installs the development/integration extras
  used by its tests instead of an incomplete core-only environment.
- Repair all five previously syntax-broken source modules. The encoded tail of
  the middleware was decoded rather than replaced with new policy. The two
  truncated endpoints had no intact version in history: their minimal request
  paths now use the existing browser client's `send_message` and return 503
  when it is unavailable, rather than fabricate a response.
- Restore `cognitive_loop.py` and `cognitive_loop_integration.py` from the last
  versions before commit `007b6f1` deleted them while retaining their callers.
- Provide the database session context-manager interface used by middleware and
  keep the async-generator interface for FastAPI dependencies. Check transaction
  commit/rollback/close behaviour with focused tests.
- Correct Pydantic 2 field validation, missing typing imports, SQLAlchemy result
  handling, setting attribute names and an invalid SQLAlchemy import.
- Make the optional evolution-router import lazy as the application intended.
  The experimental evolution API itself is not restored by this change.
- Wire startup/shutdown to existing services, use priority enum values for
  workers, and cancel lifespan-owned tasks before closing their dependencies.
- Wire basic health, metrics and alert routes to existing synchronous/asynchronous
  interfaces instead of awaiting synchronous values or invoking missing methods.
- Disambiguate test package names from production packages, register the existing
  API/alerting markers, restore real service fixtures, update HTTPX's ASGI test
  transport and adapt the accessibility tests to the installed axe API. Existing
  assertions and coverage thresholds remain in place.
- Remove the placeholder-test fallback. Continue executing collectable tests
  while still failing the job for collection errors. Generate the accessibility
  summary only when result data exists, preserving any primary test/setup failure.

## Remaining failures

Several suites assert interfaces absent from the current implementation, including
`AlertLevel`, `AlertStatus`, `ComponentStatus` and `init_metrics`. A search of this
repository's history found no definition of `init_metrics`, `AlertStatus` or
`ComponentStatus` in their named production modules. These cannot be recovered
as simple lost exports. Adding placeholders or excluding those tests would hide
an unresolved contract question.

Executed tests also expose missing profile fixtures, adaptation/pattern behaviour
mismatches, ORM tests that expect database defaults before an insert, and an auth
suite expecting a JWT interface on the separate in-memory session manager. They
remain failures; no thresholds or feature expectations were relaxed.

#119 stays open. To finish it, reconcile the intended legacy API with those test
contracts, repair the selected behaviour, then complete the PostgreSQL/Redis,
browser and coverage runs. Do not label the repository green on the basis of the
nine repaired boundary tests or the independent ADHDo 2 suite.

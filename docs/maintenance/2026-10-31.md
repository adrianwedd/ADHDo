resident instructions; root package metadata, CI workflows and entry docs;

## Repairs

| Finding | Evidence and correction |
| --- | --- |
| Boot catch-up acknowledged before injecting | Simulated tmux failure left **zero due reminders** despite failed delivery. Catch-up now acknowledges only after injection or queuing succeeds. Failure leaves reminders due. |
| Competing reminder consumers | Dispatcher and catch-up previously selected/acknowledged without a shared consumer lock. Both now use `dispatch.lock`; a concurrent-consumer test holds the first consumer during injection and checks that the second cannot deliver its reminder. |
| Atomic writes shared one `.tmp` name | Two synchronised writers reproduced `FileNotFoundError`/overwriting of temporary content. Each writer now gets a unique temporary file and cleans it up. |
| Stop on another speaker erased the resume record | Regression tests failed for both reachable and unreachable stop targets. Clearing now checks the recorded device. |
| Free-text outcomes bypassed the structured journal command | `journal log outcome "maybe worked"` succeeded despite resident instructions forbidding it. It now returns a usage error directing callers to `journal outcome`. |
| Busy hooks were not loaded by source launch paths | Hooks live in `session/settings.json`, but none of the three Claude launch commands passed it. Service, watchdog and recycle now pass `--settings` explicitly. Hook commands create/clear a temporary busy marker in tests; actual Claude loading still needs host acceptance. |
| Root pytest configuration could not parse | Reproduced duplicate `addopts` error before collection. Merged the options and corrected the section to `[pytest]`, retaining existing strictness and coverage threshold. |
| Root CI swallowed test failures | Removed the `pytest ... || echo` branch that could report a successful step after failed tests. Existing legacy failures remain visible. |
| Accessibility runner used unavailable Ubuntu package name | `libasound2` failure already recorded in #119. Updated to `libasound2t64`; host/browser accessibility is not claimed validated. The workflow now triggers for changes to its own definition. |
| New root tests were hidden by broad ignore rules | Added an exception for Python test files under `tests/`, while retaining bytecode/cache ignores. Existing tracked tests were present throughout. |
| Entry docs contradicted the current implementation | Replaced root README, quick start, docs index and repository guidance; retained previous text in `docs/archive/`. Added an ADHDo 2 installation/tool guide and corrected delivery semantics. |
| Learning claims overstated the observations | Documented that fields labelled response rates are nudge counts, and streaks count distinct recorded days. Resident instructions no longer infer `ignored` from silence or demand constant ratings. |

Four new regression cases failed before implementation (atomic write, two
wrong-device stop cases, unstructured outcome). The boot-loss reproduction
separately executed the original shell script's Python body with failed injection.
The complete ADHDo 2 suite passes **211 tests locally** after the repairs.

Python compilation of changed product tools, shell syntax, JSON/settings parsing,
root INI parsing and diff whitespace checks also pass. CI results and integration
commit are recorded on the maintenance PR.

At least three are reachable from the old server: `main.py` imports the enhanced
security middleware, background routes import cache strategies, and health routes
import database testing. These are not all safely dismissible as dead files.

The committed root dependency declarations still include unavailable package or
version names: `opentelemetry-auto-instrumentation`,
`opentelemetry-instrumentation-psutil`, and
`opentelemetry-exporter-prometheus>=1.12.0rc1`. An isolated correction experiment
proved that pip could resolve/install the core package, but exposed additional
incompatibilities: incorrect instrumentor class names/calls, SQLAlchemy 2.1 beyond
the installed instrumentor's supported range, and the retained Jaeger 1.21
exporter importing symbols removed from the current OpenTelemetry SDK. Those
exploratory dependency/source edits were **not shipped**.

After the pytest-config correction, collection in that experimental core-runtime
venv reached **35 errors**, including missing optional test dependencies, missing
application modules, invalid imports, unregistered strict markers and source
syntax errors. This was not a full `[dev]` installation and is not a claim that
all 35 failures represent distinct runtime bugs. The original CI dependency
failure remains a separate, reproducible blocker.

Next for #119: decide which legacy entry point must remain supported; restore
its truncated code from intact history where available, reconcile a compatible
runtime/test dependency set, then run actual unit/integration/accessibility tests.
Do not hide failing checks, fabricate placeholder tests or call the old server
ready because ADHDo 2 passes.
